# Простая консольная база данных

Учебный проект на Python. Реализовано управление таблицами и сохранение
их структуры в JSON. Добавлены функции хранения записей для следующего этапа CRUD.
Код организован процедурно: через функции, без классов.

## Требования

- Python 3.12 или новее; для разработки указан Python 3.14 в `.python-version`.
- uv 0.12.18 или новее.
- Make для коротких команд; без Make можно использовать команды uv напрямую.

## Установка

```bash
make install
```

Эта команда выполняет `uv sync --locked`, создаёт `.venv`, устанавливает пакет,
`prompt`, `prettytable` и инструменты разработки. Версии фиксируются в `uv.lock`.
Имя импортируемого пакета — `primitive_db`; `src/` служит контейнером исходников.

## Запуск

```bash
make run
```

Также доступны `uv run database`, `make project` и `uv run project`.

## Проверка кода и сборка

```bash
make lint
make build
make publish
```

`make publish` выполняет `uvx twine check dist/*`: проверяет метаданные
собранных файлов локально, без загрузки пакета в PyPI. Реальной публикации нет.
После сборки `make package-install` устанавливает wheel в окружение `.venv`.

## Управление таблицами

- `create_table <имя> <столбец:тип> ...` — создать таблицу.
- `drop_table <имя>` — удалить таблицу.
- `list_tables` — вывести имена всех таблиц.
- `help` — показать справку.
- `exit` — завершить работу.

Поддерживаемые типы: `int`, `str`, `bool`. Столбец `ID:int` автоматически
становится первым. Если пользователь указал его сам, второй ID не создаётся.
Повторяющиеся имена столбцов, неверный формат и неизвестные типы отклоняются.

```text
create_table users name:str age:int is_active:bool
list_tables
exit
```

После перезапуска `list_tables` снова покажет `users`. Для удаления:

```text
drop_table users
list_tables
exit
```

Создание существующей и удаление отсутствующей таблицы выводят ошибку.
Повреждённые метаданные не заменяются пустой базой: программа сообщает об ошибке.

## Хранение данных

- `db_meta.json` — словарь с названиями таблиц и списками столбцов.
- `data/<имя_таблицы>.json` — список записей этой таблицы.

Пути отсчитываются от текущего рабочего каталога. При первом чтении отсутствующие
метаданные дают `{}`, отсутствующий файл записей — `[]`. При сохранении записей
директория `data/` создаётся автоматически. Эти файлы исключены из Git.

Сейчас функции `load_table_data` и `save_table_data` доступны в `utils.py`;
пользовательские команды CRUD добавляются следующим шагом.

## Разбор values, where и set

Модуль `parser.py` разбирает литералы и выражения для будущих CRUD-команд:

- `parse_values('("Михаил", 28, true)')` возвращает список значений.
- `parse_where('age = 28')` возвращает словарь условия.
- `parse_set('name = "Анна, Мария", age = 29')` возвращает словарь обновлений.

Строковые значения должны быть в двойных или одинарных кавычках. В двойных
кавычках используются правила JSON: например, `\\` для обратного слеша
и `\"` для кавычки внутри строки. Пробелы, запятые и `=` внутри строки сохраняются.
Числа и `true`/`false` разбираются в `int` и `bool`; `"28"` и `"true"` остаются
строками. Значения `float`, `null`, списки и словари не поддерживаются.

`where` содержит одно равенство. `set` может содержать несколько присваиваний
через запятую. Повтор одного столбца в `set`, пропущенное значение и незакрытые
кавычки вызывают ошибку валидации. Разбор не выполняет Python-код.
Подключение этих выражений к пользовательским CRUD-командам — следующий шаг.

## Ядро CRUD

В `core.py` реализованы операции с записями:

- `insert(metadata, table_name, values)` загружает записи таблицы и добавляет новую.
- `select(table_data, where_clause=None)` возвращает копии всех подходящих записей.
- `update(table_data, set_clause, where_clause)` обновляет все совпадения.
- `delete(table_data, where_clause)` удаляет все совпадения.

Все функции возвращают список записей. `insert` не принимает пользовательский ID:
он равен максимальному существующему ID плюс один. Все остальные поля обязательны.
Проверка типов строгая: `true` не заменяет целое число, `1` не заменяет `bool`,
а `"28"` остаётся строкой. Обновление ID запрещено: этот столбец генерируется
автоматически. Данные проверяются до изменений, поэтому ошибка поля или типа
не приводит к частичному обновлению.

`get_table_schema(metadata, table_name)` возвращает схему для проверки полей.
Операции `select`, `update`, `delete` могут получить её дополнительным аргументом
`schema`, чтобы проверять имена и типы даже при отсутствии записей. Для `insert`
дополнительный аргумент `table_data` позволяет передать уже загруженные записи.

Функции ядра возвращают результат в памяти. Сохранение изменений через `utils`
и подключение CRUD к консольным командам добавляются следующим шагом.
