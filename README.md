# Простая консольная база данных

Учебная база данных на Python: создание таблиц, добавление, выборка,
обновление и удаление записей. Структура и данные сохраняются в JSON,
а результаты выборки выводятся через PrettyTable. Приложение написано
с помощью функций, без классов. Декораторы обрабатывают ошибки,
запрашивают подтверждение удаления и показывают время операций.
Результаты повторяющихся выборок кэшируются с помощью замыкания.

## Требования

- Python 3.12 или новее; в `.python-version` указан Python 3.14.
- uv 0.12.18 или новее.
- Make для коротких команд. Можно использовать uv напрямую.

## Установка и запуск

```bash
git clone https://github.com/zakuv/dz-database_Naumov_M26_555.git
cd dz-database_Naumov_M26_555
make install
make run
```

`make install` выполняет `uv sync --locked`: создаёт окружение `.venv`,
устанавливает пакет, библиотеки `prompt`, `prettytable` и Ruff для разработки.
Версии зависимостей зафиксированы в `uv.lock`.

Без Make:

```bash
uv sync --locked
uv run database
```

Также доступны `make project` и `uv run project`.

## Команды

| Команда | Действие |
| --- | --- |
| `create_table <таблица> <столбец:тип> ...` | Создать таблицу |
| `drop_table <таблица>` | Удалить таблицу и её файл записей |
| `list_tables` | Показать список таблиц |
| `insert into <таблица> values (<значение>, ...)` | Добавить запись |
| `select from <таблица>` | Вывести все записи |
| `select from <таблица> where <столбец> = <значение>` | Вывести подходящие записи |
| `update <таблица> set <столбец> = <значение> where <столбец> = <значение>` | Обновить подходящие записи |
| `delete from <таблица> where <столбец> = <значение>` | Удалить подходящие записи |
| `info <таблица>` | Показать столбцы и количество записей |
| `help` | Вывести справку |
| `exit` | Завершить работу |

Поддерживаются типы `int`, `str`, `bool`. Столбец `ID:int` автоматически
становится первым. Если он указан при создании таблицы, второй ID не добавляется.
Повторяющиеся имена столбцов и неизвестные типы отклоняются.

В `values` передаются все поля, кроме ID, в порядке столбцов таблицы.
ID новой записи равен максимальному существующему ID плюс один; для пустой
таблицы он равен 1. Изменение ID через `update` запрещено.

Строковые значения заключаются в двойные или одинарные кавычки.
В двойных кавычках используются правила JSON: `\"` для кавычки внутри строки
и `\\` для обратного слеша. Пробелы, запятые и знаки `=` внутри строк сохраняются.
Имена таблиц и столбцов с пробелами тоже нужно заключать в кавычки.

Проверка типов строгая: `28` — целое число, `"28"` — строка,
`true` — логическое значение, `"true"` — строка. Число `1` не заменяет `bool`.
Значения `float`, `null`, списки и словари не поддерживаются.

`where` содержит одно равенство. `set` может содержать несколько присваиваний
через запятую, например `set age = 29, is_active = false`.
Обновление и удаление затрагивают все записи, подходящие под условие.
Ключевые слова CRUD-команд можно писать в любом регистре.
Регистр имён таблиц и столбцов имеет значение.

## Пример работы

После запуска `make run` введите:

```text
create_table users name:str age:int is_active:bool
insert into users values ("Sergei", 28, true)
insert into users values ("Anna", 25, false)
select from users
select from users where age = 28
update users set age = 29, is_active = false where ID = 1
info users
exit
```

Запустите приложение повторно. Изменения сохранятся:

```text
select from users
delete from users where ID = 1
y
select from users
drop_table users
y
list_tables
exit
```

Ответы `y` в этом примере вводятся на запросы подтверждения.

## Декораторы и кэширование

`handle_db_errors` перехватывает ошибки таблиц и столбцов (`KeyError`),
валидации (`ValueError`), отсутствующих файлов (`FileNotFoundError`)
и другие ошибки файловой системы. Сообщения выводятся в консоль;
неудачная операция возвращает `None`. Движок проверяет результат
перед сохранением и продолжает принимать команды.

`confirm_action(action_name)` запрашивает подтверждение перед удалением
таблицы или записей. Например:

```text
Введите команду: drop_table users
Вы уверены, что хотите выполнить "удаление таблицы"? [y/n]: n
Операция отменена.
```

Чтобы выполнить удаление, нужно ответить `y` (также принимается `Y`).
Любой другой ответ, в том числе пустой Enter, отменяет действие.
Отмена сохраняет записи, метаданные и файлы.

`log_time` измеряет выполнение `insert` и `select` через `time.monotonic()`.
Время выводится с тремя знаками после разделителя:

```text
Функция select выполнилась за 0.001 секунд
```

`create_cacher()` возвращает функцию `cache_result(key, value_func)`
со словарём в замыкании. На первом вызове вычисляется и сохраняется результат,
на повторном вызове с тем же ключом используется сохранённое значение.

В `select` ключ учитывает содержимое записей, условие и схему таблицы,
включая типы значений. Изменения через `insert`, `update`, `delete`, создание
и удаление таблиц очищают кэш. Изменения JSON между командами учитываются
при построении нового ключа. Проверка схемы и типов выполняется до обращения
к кэшу, а вызывающий код получает отдельные копии записей.

Декораторы сохраняют имя, документацию и связь с исходной функцией.

## Хранение и обработка ошибок

- `db_meta.json` хранит названия таблиц и списки столбцов.
- `data/<имя_таблицы>.json` хранит список записей таблицы.

Пути отсчитываются от рабочего каталога, из которого запущено приложение.
Отсутствующие метаданные загружаются как `{}`, отсутствующий файл записей —
как `[]`. Директория `data/` создаётся при сохранении.
Эти файлы исключены из Git.

Успешные изменения сохраняются сразу. Для записи каждого JSON используется
временный файл с последующей заменой исходного. Удаление таблицы удаляет
также файл её записей, поэтому повторное создание начинается с пустой таблицы.

Неверный синтаксис, неизвестные таблицы и столбцы, ошибки типов и файлов
выводятся в консоль. Поля и типы проверяются до изменения записей.
Повреждённый JSON не заменяется пустыми данными. При ошибке чтения метаданных
приложение завершает работу с сообщением об ошибке. Отсутствие файла при первом
запуске обрабатывается в `utils.py` как нормальное состояние пустой базы.

## Структура кода

Пакет расположен в `src/primitive_db`. Директория `src` служит контейнером
исходников, имя импортируемого пакета — `primitive_db`.

| Модуль | Назначение |
| --- | --- |
| `main.py` | Точка входа |
| `engine.py` | Ввод команд, вызов операций и вывод результатов |
| `core.py` | Управление таблицами и операции с записями |
| `utils.py` | Загрузка и сохранение JSON |
| `parser.py` | Разбор команд и выражений `values`, `where`, `set` |
| `decorators.py` | Обработка ошибок, подтверждения, замер времени и кэшер |
| `constants.py` | Пути, типы и текст справки |

Функции ядра возвращают данные, а консольный движок сохраняет успешные изменения.
Разбор команд не выполняет пользовательский Python-код.

## Проверка и сборка

```bash
make lint
make build
make publish
```

`make lint` запускает Ruff. `make build` создаёт wheel и исходный архив в `dist/`.
`make publish` выполняет `uvx twine check dist/*`: проверяет метаданные сборки
локально, без загрузки в PyPI. После сборки `make package-install` устанавливает
wheel в окружение `.venv`.


Для проверки установленного wheel после сборки:

```bash
make package-install
.venv/bin/database
```
